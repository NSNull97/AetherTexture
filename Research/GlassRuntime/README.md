# Aether glass runtime lab

Start with [the research report](../../AetherGlassRuntimeResearch.md).

This directory is an isolated simulator experiment. It is not a SwiftPM target and is not linked into AetherUI. The main report distinguishes SDK declarations, runtime metadata, observed rendering behavior, and unverified candidates.

## Reproduce

Use an already booted **arm64 iOS 26+** simulator and the installed Xcode SDK:

```sh
python3 Research/GlassRuntime/run.py --device <UDID> --label ios27 --appearance light
python3 Research/GlassRuntime/run.py --device <UDID> --label ios27-dark --appearance dark
python3 Research/GlassRuntime/analyze.py ios27 ios27-dark
```

Repeat with the iOS 26 device and labels `ios26`, `ios26-dark`, then:

```sh
python3 Research/GlassRuntime/analyze.py ios26 ios26-dark
python3 Research/GlassRuntime/compare.py ios26 ios27
python3 Research/GlassRuntime/compare.py ios26-dark ios27-dark
```

`run.py` builds into `.build/GlassProbe`, installs `local.aether.glassprobe`, collects six fresh JSON files and a settled simulator screenshot, and terminates the app. It changes appearance only inside the probe. It does not alter system accessibility or glass preferences. The exact Aether luma container source is extracted at build time to test its Objective-C selector exposure; its source hash is recorded.

## Evidence files

For each label, `results/` contains:

- `environment.json`: SDK, Xcode, runtime, source/probe hashes, git revision.
- `inventory.json`: matching classes, own methods with ABI encodings, properties, ivars, protocols and selector matches.
- `hierarchy.json`: all 18 cases, descriptors, full window tree, and enclosing render containers.
- `objects.json`: isolated CASDF defaults, CAFilter type inventory, luma selector check and style comparison.
- `strings.json`: relevant `__cstring` entries from six loaded system framework images.
- `materialization.json`: layer animations after nil → glass.
- `materialization-empty.json`: layer animations after empty effect → glass.
- `summary.json`: address-normalized rendering data and aggregate counts.
- `grid.png`: light or dark screenshot.

The full catalogs are generated by `analyze.py`. Their broad name filter includes false positives such as scene materials or image-processing glass filters. A method appearing in a class's own method table can be an override; this alone does not establish its introduction version. A nil KVC result is not proof that a key is unsupported, and a successful setter call is not proof of a rendering effect.

## Local environment used

- iOS 27.0 (24A434), iPhone 18 Pro: `D0AE9B34-436F-4D77-927C-AD820F80D10B` (pre-existing device).
- iOS 26.0 (23A343), iPhone 17 Pro: `D8CA274B-C4EE-4B5A-B73B-115BED77B1D9` (created for this research).

The official iOS 26 runtime was downloaded through `xcodebuild -downloadPlatform iOS -buildVersion 26.0 -architectureVariant arm64`. Both apps were compiled with SDK 27 and deployment target 26.0. The dedicated iOS 26 simulator is shut down after research; its runtime and device remain available for subsequent experiments.
